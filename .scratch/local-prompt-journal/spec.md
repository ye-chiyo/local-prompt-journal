# 本地 Codex 对话日志与提示词改进工作台：首版规格

日期：2026-10-25（Asia/Shanghai）

Status: ready-for-agent

测试边界：用户于 2026-10-25 明确确认整体链路验收与真实 Codex 接口兼容性检查。

本规格综合当前讨论，不代表已完成实现或兼容性测试。用户已确认 Codex 桌面端优先、日志全部留在本机、主要用于改进提示词。下文明确区分已确认约束、建议采用的首版设计，以及必须通过实测决定的事项。

2026-10-25 需求修订：日常使用只保留自动同步；项目分别归档，同一项目按会话开始时间从早到晚排列完整会话，不跨会话交错消息。该修订已获用户确认并授权记录，取代此前的手动选择采集流程，见 [ADR 0001](../../docs/adr/0001-automatic-project-archive.md)；任务 03、04 合并交付，尚未实施。

## Problem Statement

用户使用 Codex 桌面端开展任务，希望完整回看自己输入的提示、AI 可获取的输出和工具执行证据，弄清哪些要求表达不清、哪些要求是在多次纠正后才补充，以及哪些问题实际上来自工具、环境或执行行为。

目前缺少面向提示词改进的可检索、可标注、可比较的本地记录。仅保存最终回答会遗漏过程；让当前 agent 自行整理日志会增加上下文与执行负担；仅依赖回合正常结束后的触发又可能漏掉中断和异常过程。

用户没有外部服务器，要求日志全部留在本机。首版应在这个约束下实现可靠记录和人工复盘，不要求额外购买云服务或运行本地大模型。

## Solution

提供一个单用户、单机运行的对话证据库及复盘界面。外部采集器从当前 Codex 的可读取历史中增量归档数据，用轻量通知和周期对账发现更新；用户可以按项目或会话查找提示、回答、工具参数与结果，查看回合时间线，并从每条展示记录返回原始证据。

采集器自动发现本机支持来源中的项目、新会话及更新，不要求逐项目／会话勾选或点击手动同步。多个项目同时工作时分别归档；同一项目内按来源会话开始时间从早到晚排列，每个会话内部保留原有回合和消息顺序。较早会话收到新消息时，内容仍补入原会话，不按最近活跃时间重排会话，也不插入其他会话正文。

用户可以对结果做轻量标注，将后续纠正关联到原提示，并保存提示改写版本及修改原因。系统展示事实和比较材料，不自动认定提示词造成了失败，也不承诺某个改写一定有效。

交付分为连续的两个阶段：先证明当前桌面数据源的可访问性与覆盖边界，再交付采集、检索、标注和比较的最小闭环。如果数据源不能覆盖关键证据，应输出缺口与适配结论，不将只能读取部分聊天的演示宣布为完整采集产品。

## User Stories

1. 作为 Codex 桌面端用户，我希望日志在本机自动保存，以便无需每轮手动复制对话。
2. 作为用户，我希望采集过程不要求 agent 额外调用模型，以便减少对原任务的干扰。
3. 作为用户，我希望日志内容不被重新注入正在运行的对话，以便避免占用上下文。
4. 作为用户，我希望采集、检索和复盘不上传日志，以便满足全部留在本机的要求。
5. 作为用户，我希望本机支持来源中的新项目、会话及更新被自动发现和归档，以便多项目并行时无需记得选择会话或手动同步。
6. 作为用户，我希望查看每次用户提示的原文，以便准确还原当时的要求。
7. 作为用户，我希望查看可取得的 AI 过程消息和最终回答，并区分它们，以便理解回应顺序。
8. 作为用户，我希望查看工具名称、参数、返回结果和可取得的执行状态，以便判断工具是否被正确使用。
9. 作为用户，我希望工具请求和对应结果能够关联，以便避免把并行执行的结果混淆。
10. 作为用户，我希望后台任务的启动、轮询和最终退出能够关联，以便区分已启动与已完成。
11. 作为用户，我希望区分主会话、子 agent 和分叉会话，以便追踪任务分工和不同尝试。
12. 作为用户，我希望中途取消的回合仍保留已取得的证据，以便复盘未正常结束的任务。
13. 作为用户，我希望清楚看到缺失、截断和未知状态，以便不把没有记录误解成没有发生。
14. 作为用户，我希望采集器重启后补回数据源中仍可取得的记录，以便临时关闭采集器不会永久造成可恢复数据的遗漏。
15. 作为用户，我希望重复读取同一批历史不会产生重复记录，以便检索结果和统计保持可信。
16. 作为用户，我希望同一句提示在不同时间真正发送两次时都被保留，以便记录真实交互次数。
17. 作为用户，我希望进行中的工具条目随后能显示最终结果，以便看到完整的状态变化。
18. 作为用户，我希望按项目和会话浏览记录，以便找到相关工作。
19. 作为用户，我希望搜索中文提示、AI 回答和工具错误文本，以便定位过去遇到的相似问题。
20. 作为用户，我希望从搜索结果跳到对应回合和原始证据，以便核对上下文。
21. 作为用户，我希望将结果标为满意、需要修改或不可用，并记录原因，以便为改进积累结果依据。
22. 作为用户，我希望标注可以稍后修改且无需每轮强制填写，以便按自己的复盘节奏工作。
23. 作为用户，我希望把后续纠正关联到原提示或具体输出，以便识别重复出现的要求遗漏。
24. 作为用户，我希望保存改写后的提示版本和修改原因，同时保留原版，以便比较变化。
25. 作为用户，我希望提示版本能够关联实际使用案例和人工结果标签，以便区分设想中的改进与有证据的改进。
26. 作为用户，我希望模型、环境及上下文相关信息在可获取时一起展示，以便避免把其他条件变化误判为提示效果。
27. 作为用户，我希望没有模型或统计数据时仍能完成检索、标注与版本比较，以便首版可在普通本机环境使用。
28. 作为用户，我希望导出选定会话的结构化记录和证据清单，以便离线备份或进一步分析。
29. 作为用户，我希望删除日志系统中的选定会话时同步清理它的派生数据，以便控制本机数据保留范围。
30. 作为用户，我希望查看采集进度、最近成功同步和错误状态，以便知道当前记录是否仍在更新。
31. 作为用户，我希望数据源不可用或格式不支持时得到明确说明，以便不会把空列表误认为没有历史。
32. 作为用户，我希望浏览历史不会重新执行历史命令或恢复原会话，以便复盘不改变原任务。
33. 作为用户，我希望同时进行的不同项目分别记录，以便不会混入其他项目的对话。
34. 作为用户，我希望同一项目的会话按开始时间从早到晚排列，每段会话完整展示，以便交替工作时仍能分别回看。

## Implementation Decisions

### 已确认约束

- 首个支持目标为用户当前 Windows 环境中的 Codex 桌面端；其他平台留作后续扩展。
- 所有新增日志采集、存储、检索、标注和分析均在本机完成。新增组件不得向远端发送日志、提示、附件、标注或日志派生数据。
- 原有 Codex 本身的模型通信与新增日志系统分开界定；本地日志系统不承担使原有 Codex 离线运行的目标。
- 采集器在模型对话循环之外运行，不要求当前 agent 编写日志，不额外调用模型，不向其上下文返回归档或分析内容。
- 首版的主要用途是改进提示词，执行追踪为证据基础，不扩展为团队运维平台。
- 日常采集仅使用自动发现和持续同步，不以手动选择项目／会话、手动同步或手动导入作为正常使用前提；当前版本已有手动导入命令不代表该新需求已实现。
- 项目与会话身份分别保留，不因名称或文本相同而合并；会话按来源开始时间升序排列，缺失开始时间标为未知，不使用采集时间冒充。

### 建议采用的首版模块与职责

- 数据源适配：探测当前桌面版本及历史读取能力，提供按范围枚举会话、分页获取回合/条目和报告能力缺口的统一接口。
- 采集协调：接收更新提示、周期对账、保存断点、重试读取，回查活动回合并处理状态修订。
- 证据归档与索引：保存来源实际返回的原始记录、附件及引用；规范化索引用于搜索和关联，原始证据用于核对与重建。
- 复盘应用：提供会话时间线、全文检索、反馈标注、纠正关联、提示版本比较以及结构化导出。
- 这些是职责边界，不要求部署成独立服务或逐个暴露测试接口。首版优先一个本机进程与一个本地数据目录。

### 采集契约

- 优先验证正式历史读取接口；hook 用于轻量更新通知或补充证据；仅在证实适用时使用旧日志文件兼容适配器。不能预设所有桌面会话都具有完整的旧式 JSONL。
- 能力探测结果应标明支持的消息类型、工具记录范围、分页能力、缺失字段及数据源版本。接口返回摘要时不得当作原文归档。
- 读取接口须保留来源身份、会话/回合/条目身份、原始载荷、来源顺序或关联关系、源时间和采集时间；缺失字段保持未知。
- 重试和重复通知可以发生，最终归档和展示必须去重。去重依据来源身份与事件身份，不依据文本相同。
- 同一条目后续取得完成状态或更完整内容时，保存可追溯修订，并在视图显示当前状态。不能只向前移动断点而永久跳过未完成条目。
- 断点不能领先于对应数据的持久保存。异常恢复允许重复读取，不能将尚未保存的数据当作已处理。
- hook 丢失时，可从历史补回的内容应在后续对账中恢复；数据源未保存或已删除的内容只能标记缺失。
- 采集失败不触发原 agent 继续、停止或修改提示。日志系统通过自己的状态界面报告问题。
- 自动发现多个项目和会话，独立跟进各自更新与失败；来源断开不显示成真实空列表，一个会话失败不冒充其他会话也失败或全部成功。
- 自动归档仅覆盖本机支持来源，不能绕过来源访问限制；来源不支持的项目归属或会话显示实际缺口，不凭标题猜测归属。首次启动回补多少既有历史仍待确认，不擅自假定只采新会话或立即导入全部旧历史。

### 本地存储与数据关系

- 建议采用本地文件保存原始证据和大附件，SQLite 保存索引、关联和人工标注。具体语言与界面框架不在本次讨论中锁定。
- 实际日志数据与项目源码分离存放，避免未来提交源码时携带日志。服务式界面仅绑定本机回环地址。
- 会话包含来源实例、项目、会话身份及可取得的父子/分叉关系；回合包含状态及可取得的模型、时间和上下文元信息。
- 来源提供项目身份时以该身份区分，工作目录可作为归属依据；归属无法可靠确定时单列“项目未知”，不混入已知项目。并行会话分别保存，不将不同会话的消息组成一条交错时间线。
- 会话排序依据来源会话开始时间，而非最近消息时间或采集到达顺序；开始时间相同或未知时保持稳定且说明规则，不伪造时间。用户提问、AI 过程消息和最终回答直接展示，工具及其他非对话条目按回合收进默认折叠的“执行过程”。
- 事件包含来源身份、类型、角色或消息阶段、调用与父调用关系、顺序、内容引用和完整性状态。完整性至少区分完整、部分和未知，并记录原因。
- 工具的执行状态与业务成功分别记录；未知退出状态不等于成功。后台进程句柄不等于最终执行结果。
- 人工标注关联具体会话、回合或条目；提示版本关联原版、修改说明及可选的使用案例；所有比较保留原始文本。
- 缺失的时间、耗时、token、错误码和配置不伪造默认值。无法恢复的隐藏信息、截断部分和附件明确标记。
- 中文检索必须用真实中文样本验收；实现可选分词或子串策略，但不能以只搜标题或用户提示代替全文搜索要求。
- 导出包含结构化记录、证据引用和缺失清单；已取得附件随导出可离线访问，未取得附件不得宣称已备份。
- 删除功能作用于日志系统自己的归档、索引、附件引用、标注和派生结果，不能删除 Codex 原始会话。共享附件仅在无剩余引用时清理；已导出且不受应用管理的副本不承诺远程擦除。保留删除排除标记，防止下一次同步自动重新导入；只有用户显式解除排除后才允许重新自动归档，不恢复日常手动同步流程。

### 提示词改进交互

- 人工结果标签采用满意、需要修改、不可用；原因说明与纠正关联均可编辑。
- 首版由用户关联纠正、维护提示版本和查看案例。自动归因、自动改写和实验执行属于后续能力。
- 对比视图区分原始事实、人工判断和待验证建议；对模型或上下文不同的案例展示已知差异，不输出未经验证的因果结论。
- 不以追问次数或工具报错次数单独判断质量；它们仅可作为定位线索。

### 实施前必须解决的事实问题

- 当前桌面运行实例可采用的只读连接方式，以及目标会话是否可见。
- API 或兼容日志对普通消息、工具结果、嵌套调用、子 agent、后台任务和截断内容的实际覆盖率。
- 现成查看器能否处理该数据源。优先复用经验证的适配/展示能力，尚未选定任何第三方项目作为依赖。
- 首次导入、增量同步的耗时和资源开销。不得在没有基准测试时承诺零开销；数值预算应根据可行性验证形成独立决策后再作为性能发布门槛。

### 待确认事项

- Windows 登录后是否自动启动采集器：目前仅为建议，未获确认，不写成已实现或必需的开机配置。
- 首次运行对既有历史的回补范围：需在真实批量归档前明确，不以本次文档提交代替用户决定。自动发现新会话及运行中更新、中断后补回已纳入归档的来源记录已经确认。

## Testing Decisions

### 已确认的主要测试边界

以“本机日志应用的对外行为”为一个主要测试边界：输入受控会话历史，经过真实的采集、持久保存、索引和复盘流程，从公开查询/导出结果及用户界面验证结果。

测试只替换最外部 Codex 数据源，不逐层模拟采集器、数据库或索引。这样实现可以更换内部模块，仍由相同的业务验收保护行为。

由于受控数据源不能证明真实桌面兼容，另外保留一个薄的真实连接契约检查：以无敏感样本验证实际读取接口与受控样本的关键字段、身份、分页及状态语义一致。该检查不重新实现整套业务测试，也不调用历史中的工具。需要产生新样本时遵守原 Codex 的正常交互流程，不能声称该样本生成过程完全离线。

### 好测试的标准与现有基础

- 测试观察用户能看见或导出的内容、状态和关联，不断言内部函数调用次数、私有表名或具体框架结构。
- 预期事件由事先定义的样本清单确定，不能用采集器自己的输出作为完整性判断的唯一依据。
- 初始规格发布时只有调研和配置文档；当前任务 01、02 已验收，已有应用与公开行为验证可复用。本次仅修订规划，不宣称新增自动归档能力已通过测试。
- 主要覆盖数据源适配后的完整采集/归档/查询链路，以及人工反馈和提示比较行为；真实来源适配由薄契约检查补充。

### 必须覆盖的验收场景

1. 正常会话：提示原文、AI 各阶段消息、工具参数和结果均与预设样本一致，并能定位原始证据。
2. 并行与重复文本：并行工具结果配对正确；两次相同提示保留为两条；重复导入不增加重复条目。
3. 状态更新：工具先进行中后完成，当前视图正确更新，历史证据仍可追溯。
4. 中断与后台进程：取消回合保留已取得内容；启动、轮询、退出能够关联，缺少退出记录时状态未知。
5. 子 agent 和分叉：父子与分叉关系可浏览，不将独立会话的事件合并到同一回合。
6. 分页与恢复：读取过程中停止采集器，恢复后源中可读取的数据无遗漏；分页重叠、重复通知、漏通知不破坏最终结果。
7. 截断与不支持：长输出、缺附件、不支持的事件和未知格式均如实标注，不静默显示完整成功。
8. 中文全文搜索：分别搜索仅存在于用户提示、AI 回答和工具输出中的中文词组，均返回正确结果及证据位置。
9. 人工复盘：添加和编辑结果标签、纠正关联、提示版本后重启，数据仍存在且原始内容未被改写。
10. 导出：离线打开导出的结构化内容和已取得附件，无需远端请求即可核对样本；缺失项明确列出。
11. 删除：目标会话的受管理数据不再可查，其他会话和 Codex 原会话不受影响；同步后不会未经显式恢复重新出现。
12. 隔离：新增日志组件无远端数据发送；正常采集与复盘不产生额外模型调用、不向原会话注入内容、不恢复会话或执行历史命令。
13. 故障报告：数据源断开、存储写入失败或解析失败时，用户能看到失败及最近成功状态；恢复后可以继续对账。
14. 性能记录：在相同受控样本和运行条件下记录启用前后的回合耗时、采集延迟、CPU、内存与磁盘写入。功能通过不替代性能验证。
15. 多项目自动归档：两个项目并行产生新会话和消息，无需手动同步即可分别保存；同名会话不会串项目，不可访问会话有明确状态。
16. 项目内会话顺序：A 在 10:00 开始、B 在 10:01 开始、A 在 10:02 又有消息时，仍先展示完整 A 再展示完整 B；组内消息顺序和工具所属回合保持不变。

本节列出首版整体的验收方法；任务 01、02 已有验收记录，新增自动归档、多项目与排序要求尚未实施或验证。

### 用户确认与提交节奏

- 每次交付一个用户可体验的完整功能：实现、必要功能验证及代码检查后交给用户验收；用户明确确认通过后，才登记完成并提交一次相关 commit。不得为实现、修复、文档或审查预先创建临时 commit，不自动 push。
- 只验证用户能感知的公开行为；预期来自独立样本或已确认要求，不以程序输出反推答案，不测试内部表名、私有函数或调用次数。修 bug 优先复用已有验证，只在重要回归缺口处补最少检查，不扩展无关测试和细节。

## Out of Scope

- 多用户、团队权限、远端服务器、云端同步、跨设备实时协作。
- 首版同时支持 Claude Code、浏览器聊天产品或任意第三方 agent。
- 云端日志分析、云端提示改写，以及要求额外模型的自动复盘。
- 本地模型接入、向量数据库、自动聚类、自动因果诊断和自动生成提示。
- 自动重新运行历史命令、自动 A/B 实验、自动修改原会话或项目指令。
- 获取未公开的系统信息、隐藏思维过程、数据源已经丢弃的内容。
- 保证所有数据源所有工具类型永远完整，或宣称性能零开销。
- 加密备份系统、自动保留期限与跨设备迁移；首版提供本地结构化导出及受管理数据删除。
- 自动采集整台电脑任意应用的一切历史。首版仅自动归档本机支持的 Codex 来源，不要求用户日常逐个选择项目／会话；来源访问限制和删除排除仍有效。
