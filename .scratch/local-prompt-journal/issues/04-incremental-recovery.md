# 04 — 持续同步并在中断后补回记录

**What to build:** 用户选定采集范围后，新回合和工具状态自动更新；采集器退出再启动、重复通知或遗漏通知后，能够从来源中仍存在的历史恢复一致记录。

**Blocked by:** 02 — 查看工具参数、结果与执行状态；03 — 选择项目与会话的采集范围

**Status:** ready-for-agent

- [ ] 周期对账可独立发现新数据；接入 hook 时只作轻量通知或补充，按来源协议返回，不输出注入模型的上下文。
- [ ] 重复读取、分页重叠和重复通知不增加重复条目；真实发送两次的同一句提示仍保留两次。
- [ ] 进行中的工具和回合可更新为最终状态，并保留可追溯修订；回查最近活动数据，不因已越过断点而永久遗漏完成结果。
- [ ] 断点仅在相应数据持久保存后推进；读取、保存或进程退出失败后可重试，并补回来源仍保留的记录。
- [ ] 回合中断保留已取得内容；来源已丢弃的数据明确标记缺失，不伪造恢复成功。
- [ ] 状态界面显示同步状态、最近成功时间和错误；数据源断开及存储失败不会显示为正常空数据。
- [ ] 以分页边界、重复/漏通知、写入失败、进程停止恢复和进行中状态变化验收实际存储与公开查询链路。
- [ ] 记录同步延迟与基础资源开销，正常同步不额外调用模型、不改变原会话执行。
