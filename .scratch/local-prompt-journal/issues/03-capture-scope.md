# 03 — 多项目自动归档与持续同步

**What to build:** 采集器自动发现本机支持来源中的项目、新会话及更新，持续归档并在中断后补回可恢复记录；用户按项目分别浏览，同一项目按会话开始时间从早到晚查看完整会话，不需要逐会话勾选或手动同步。

**Blocked by:** 01 — 读取一段真实会话并在本机查看、导出；02 — 查看工具参数、结果与执行状态

**Status:** ready-for-agent

- [ ] 自动枚举支持来源中的项目及会话，并持续发现新项目、新会话和消息更新；日常采集不以手动选择、手动导入或点击同步为前提。来源不可访问与确实没有会话显示不同状态。
- [ ] 两个项目并行时分别归档，跨会话保留来源、项目、会话、回合及条目身份；不因同名项目、同名会话或文本相同而合并。无法可靠取得项目归属时单列“项目未知”，不凭标题猜测。
- [ ] 同一项目按来源会话开始时间升序排列完整会话；A 10:00 开始、B 10:01 开始、A 10:02 更新时，仍为完整 A、完整 B，不交错消息，不按最近活跃时间重排。缺失开始时间标为未知，相同或未知时间采取稳定且明确的排列规则。
- [ ] 会话内部保留原有回合及消息顺序；用户提问、AI 过程消息和最终回答直接展示，工具及其他非对话条目继续按回合收进默认折叠的“执行过程”。
- [ ] 周期检查可独立发现更新；hook 如有接入仅作轻量通知或补充，不注入模型上下文。重复读取、分页重叠及重复通知不重复归档，实际发送两次的相同提示仍保留两次。
- [ ] 回查最近活动记录，使进行中的工具和回合能更新为最终状态，并保留可追溯修订；不因已越过断点而永久遗漏完成结果。
- [ ] 数据持久保存后才推进断点；读取、存储或进程中断后可重试，恢复运行自动补回来源仍保留的记录。已丢弃内容标为缺失，不伪造恢复成功；一个会话失败不掩盖其他会话的实际结果。
- [ ] 页面显示后台采集状态、最近成功时间和错误；关闭查看页面不作为停止后台采集的条件。删除排除在后续任务 10 实现后仍须阻止被删会话自动回流。
- [ ] 通过两个项目、多会话、新会话发现、不可访问会话、重启恢复和重复检查的公开行为验收，预期独立定义；真实来源兼容性另作薄契约核对，不以固定样本认证真实覆盖率。
- [ ] 沿用本机处理、只读来源、代理防护、源码外数据和完整导出约束；不额外调用模型或修改原会话。记录基本同步延迟与资源开销，不扩展附件备份、后台任务关系或其他后续功能。
