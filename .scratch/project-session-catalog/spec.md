## 方案

### 1. 独立保存轻量会话摘要

新增可重建的会话摘要投影，以 `(instance, thread)` 为唯一键。保存项目身份及名称、会话身份及名称、来源开始时间、最近保存时间和最新快照编号等基本信息。摘要中不包含消息、工具参数与结果或证据载荷。为兼容既有 `sessions()` 公开返回结构，保留来源协议元数据 `source`（实例、版本、采集范围及缺口等，不含正文）；页面只使用必要信息，按需目录 API 仅返回来源实例。

为项目筛选和稳定排序建立组合索引。项目计数、目录查询和搜索范围选项从摘要读取；保留已有公开查询的返回兼容性，避免为了优化单个页面破坏 CLI 和已有调用方。

已有库在启动就绪前做一次有进度、可恢复的摘要回填。只处理每个会话的最新快照，逐条提取元数据；把该阶段的耗时单独记录。历史库缺少 `createdAt` 或项目投影时，沿用现有 `thread` 元数据推导规则。正常项目请求不临时回退到完整快照扫描；摘要未就绪时给出明确状态。

保存新快照与更新摘要处于同一事务；受管理删除同步清理对应摘要，删除排除与解除排除遵循现有规则。重启、重复回填及多来源同 ID 不产生重复目录。保存无变化时仍核对迁移后的摘要可用性。

完整 `snapshots.package` 及来源证据保持为原始数据；摘要可重建，不用缩写正文替换原快照。

### 2. 项目页在数据库中分页

建议新增项目目录公开查询，例如 `project_sessions(project_id, offset=0, limit=30)`，返回项目基本信息、总数、当前页摘要和下一页位置。

建议 URL：`/project/<id>?offset=0&limit=30`；默认 30 条、上限 100 条。参数先校验，非法值返回清晰的 400，未知项目返回 404，越界页有返回有效目录页的入口。

数据库执行项目筛选、排序、`LIMIT/OFFSET` 和计数，禁止先读取全部完整会话再切片。分页查询和总数使用一致的读取视图。固定数据集上翻页无重漏；采集并发变化后允许目录反映新状态，返回链接仍保留原页参数。暂不增加跨请求历史目录快照机制。

目录项展示名称、来源开始时间、最近保存时间及现有必要的来源区分信息。名称缺失时使用会话 ID；时间未知如实显示。保持现有“数据库与采集状态在前、目录居中、搜索在后”的布局。

搜索表单保留全局、项目和会话范围能力，但项目页初始 HTML 不再嵌入全库会话选项。全库会话选择按需加载，可分页或按名称筛选；目录页默认搜索当前项目。

`/api/version` 从轻量摘要修订信息及必要采集状态生成版本标识，不能每 1.5 秒解析全库最新正文。版本应反映新增、更新、删除和相关状态变化。

### 3. 详情与返回路径

目录链接继续使用 `/session/<id>?source=<instance>`，按需进入现有详情页。保留 `saved` 固定版本、大文本展开加载、工具和执行过程展开、搜索定位以及来源证据链接。

从目录进入详情时携带并校验站内返回位置，优先返回所属项目的原分页位置。不得将任意外部返回地址直接作为跳转目标。直接进入详情时提供所属项目入口；首页入口仍可访问。

搜索结果保持来源、保存版本、条目位置及证据身份；浏览器后退能恢复查询和分页状态。处理实时刷新后 URL、展开与命中定位的连续性。

## 验证边界与判据

用户授权按本方案实施后，按以下公开测试边界逐条红绿推进；实际回归与结果见交验记录。

| 边界 | 验证内容 | 边界之外的证据 |
| --- | --- | --- |
| Journal 公开目录／保存／删除入口 | 多项目、多来源、稳定排序、分页、迁移与摘要随写入删除更新；正文增大不影响目录载荷 | 用 SQL trace／查询计划单独验证请求不访问 `snapshots.package`，避免只靠 HTML 测试推断 |
| HTTP 页面与实际浏览器 | 初始 HTML 无正文或工具载荷，打开详情、展开、搜索定位与返回，分页参数及错误行为 | 正式规模、响应时间、内存等通过真实库测量验证，临时夹具不代表真实性能 |

按一条纵向行为一条回归的顺序红绿推进。分页用超过两页的受控样本，因为真实库目前仅有 14 个会话；受控样本还覆盖相同时间、未知时间、同 ID 不同来源和旧会话更新。

建立覆盖项目页及其自动版本请求的反馈命令：如果读取完整快照、嵌入正文或页面外会话选项无限增长，则失败。首次回填与主动搜索读取正文属于不同阶段，分别记录。

### 真实库性能验证

1. 先用 SQLite 一致性备份生成源码外的真实库副本；备份完成并核对后才执行摘要迁移。原始归档不进入 Git 或报告，不对活跃数据库做普通文件复制。
2. 在相同真实数据副本、相同服务模式、采集暂停的受控条件下测旧实现与新实现，临时服务仅绑定回环地址，选择空闲端口。源码外保留备份、原始度量与浏览器产物。
3. 首次服务请求、摘要回填和预热后请求分别计时；建议预热 3 次、正式采样 20 次，记录中位数、P95、首字节时间、完整响应时间和 UTF-8 响应字节数。记录基线提交、数据库规模、请求路径、分页大小和缓存条件；进程首次请求不冒称操作系统冷缓存。
4. 页面体积包括目录、状态区和搜索控件；记录打开页面后一段空闲期的网络请求，证明没有自动请求任何会话正文、工具结果或证据。检查 `/api/version` 的耗时及数据库访问。
5. 对比表给出真实数值和改善比例。建议预算为默认 30 条目录页预热后 HTTP P95 ≤ 500 ms、HTML ≤ 200 KiB；这是待实测校准的目标，不是用户已确认的门槛，也不是当前测得结果。结构性要求“不预读正文、真正分页”必须独立通过。
6. 在副本通过后，对正式库进行有备份的迁移与实际路径复核；固定正式数据目录并沿用现有启用时间。恢复运行使用 `run --port 8766`，不使用 `--start-from-now`。执行前重新检查端口和进程，因为准备阶段的进程状态可能变化。

### 浏览器路径

- 项目列表 → 项目目录 → 翻页 → 点击会话 → 阅读用户／AI 原文 → 展开执行过程与长工具结果 → 打开原始证据 → 返回原目录页。
- 项目内搜索 → 打开命中 → 自动展开与高亮 → 核对命中时保存版本的证据 → 浏览器后退恢复搜索 → 返回项目目录。
- 直接打开详情、未知项目、空项目、非法分页、越界分页和窄屏阅读分别检查。
- 删除一致性在受控临时库验证，不删除正式会话。
