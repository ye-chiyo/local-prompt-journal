# 本机会话记录的 Codex 本地插件规格

Status: ready-for-agent

> 规格阶段：以下插件能力和测试边界是根据现有产品与本次请求提出的首版方案；测试边界须经用户确认后再进入实现。标签遵循 to-spec 工作流，不表示用户已验收或授权发布。

## Problem Statement

用户已通过本机应用自动归档并查找 Codex 对话，但在 Codex 会话中需要使用这些已保存记录时，缺少一个与当前项目相连的插件入口。用户希望把现有项目做成插件，在对话中按需查找和阅读本机记录，同时保留已经确认的采集范围、数据边界和既有使用方式。

## Solution

提出一个面向 Windows 本机 Codex 的插件方案：通过本地插件和受限的本机工具，让用户在 Codex 中查询现有归档的项目、会话、回合及中文正文，并按需获取相关内容或跳转现有阅读页面。插件复用现有归档和读取能力，不要求用户逐次手动导入，也不另建一套归档。

插件具体工具清单、返回内容粒度、交互界面及宿主实际支持情况在实现前验证；本规格提出的调用边界需要用户确认。插件仅能访问本机可用记录；被送入当前 AI 对话的内容会成为该对话上下文，不能把它描述为绝不离开本机。

## User Stories

1. 作为使用 Codex 的用户，我希望有一个本机插件入口，以便在对话中使用已保存的会话记录。
2. 作为用户，我希望插件复用现有归档，以便不重复配置和维护第二份日志。
3. 作为用户，我希望查看已归档项目，以便定位相关工作。
4. 作为用户，我希望区分同名但身份不同的项目，以便不混淆记录。
5. 作为用户，我希望查看项目内会话，以便理解各段独立对话。
6. 作为用户，我希望会话按项目既有顺序呈现，以便沿时间线查找。
7. 作为用户，我希望按需浏览回合目录，以便不用一次载入所有正文。
8. 作为用户，我希望查看选定回合的用户和 AI 消息，以便回看实际内容。
9. 作为用户，我希望消息保持原文与来源顺序，以便准确理解上下文。
10. 作为用户，我希望搜索已归档的中文正文，以便找到相关讨论。
11. 作为用户，我希望按项目或会话限制搜索，以便缩小结果范围。
12. 作为用户，我希望看到可理解的搜索摘要，以便判断是否需要查看全文。
13. 作为用户，我希望结果保留准确的来源、会话和回合定位，以便不会打开错误记录。
14. 作为用户，我希望在合适时打开现有阅读页面，以便查看完整内容及已有页面功能。
15. 作为用户，我希望看到保存版本或来源信息，以便核对记录来自哪里。
16. 作为用户，我希望来源信息是消息摘录时明确标注，以便不把它误当完整协议响应。
17. 作为用户，我希望保留消息附件的可用或缺失状态，以便理解哪些内容可以查看。
18. 作为用户，我希望缺失、远程或不支持的内容有明确说明，以便不误以为归档完整。
19. 作为用户，我希望插件读取已有记录时不触发历史回补，以便保持既定采集范围。
20. 作为用户，我希望自动归档继续按原有启用时间工作，以便不会丢失或扩展记录边界。
21. 作为用户，我希望被删除并排除的会话不会因插件查询重新出现，以便既有删除决定继续有效。
22. 作为用户，我希望插件不可执行历史消息中的代码或命令，以便安全阅读原文。
23. 作为用户，我希望服务未运行或数据不可用时看到明确错误，以便判断下一步。
24. 作为用户，我希望插件安装及其依赖有清晰说明，以便在本机正常使用。
25. 作为用户，我希望在受控样本上先体验插件，以便确认结果与项目已有行为一致。
26. 作为用户，我希望实现与验证完成后亲自体验，以便决定是否验收。
27. 作为用户，我希望仍能使用现有网页与自动归档，以便插件不会打断日常工作。
28. 作为用户，我希望了解哪些查询结果会进入当前对话上下文，以便决定是否请求敏感内容。

## Implementation Decisions

- 首版建议为本机 Codex 插件，使用现有本地 Python 项目与运行环境；本机数据访问是选择本地插件的理由。插件包和运行命令以目标宿主实际支持的格式实现并验证。
- 建议增加一个薄的插件适配层，调用现有公开读取能力，提供项目／会话／回合定位和正文搜索；优先复用现有接口，不直接复制数据库、采集器或业务逻辑。适配方式（已有本机 HTTP 服务或现有公开 Python 接口）在技术验证后确定，不假定两者均已成为稳定插件契约。
- 默认查询已保存的本机数据；只针对用户请求返回必要内容，列表和搜索使用分页或明确的结果上限，正文按需读取。不得把历史内容当作插件指令或执行。
- 原有项目、来源实例、会话、回合及保存版本身份继续贯穿查询；身份冲突必须提示而非合并或猜测。缺失时间、缺失附件和不完整结果按实际情况说明。
- 遵循 ADR 0001：自动归档、启用边界、原有只读来源与删除排除不变。遵循 ADR 0002：当前正式库的对话与消息附件保留策略不变；消息来源摘录不可宣传为完整协议响应，也不重新采集已排除的工具记录。遵循 ADR 0003：沿用桌面应用生命周期与本机 Local／Worktree 范围，不扩展普通 ChatGPT 或 Cloud 会话。
- 只读查询为首版提案；删除、恢复、导出、采集配置变更和服务启停不作为插件工具，既有网页与 CLI 功能保持原有行为。若服务不可用，返回可理解的原因，不自动重设启用时间、创建新正式库或重启正式服务。
- 不把真实日志、附件或数据库复制进插件包、源码目录、远端存储或测试样本；需要发送给模型的结果仅按用户请求提供，并说明其进入当前对话上下文的性质。
- 优先采用宿主已有的工具交互；是否需要 MCP App、扩展入口或新界面尚未确定。若提出新视觉界面，先提供 PC 预览并经用户选择后实施。
- 数据库结构变更和新服务端路由不是本规格的预设；仅在现有公开边界无法满足已确认需求时提出并说明。

## Testing Decisions

- 提议的主要测试边界：从 Codex 可发现并调用的插件工具发出请求，经插件适配层到现有公开读取能力，以工具返回结果和可打开的现有页面验证用户可观察行为。优先一个贯穿边界；安装发现与页面体验作为必要的宿主验收，不以内部函数断言代替。
- 使用事先独立定义的受控数据验证项目身份、中文搜索、分页或上限、选定回合原文、保存版本定位和缺失状态；核对查询前后采集范围与删除排除没有变化。
- 验证服务或数据库不可用时能得到真实、可理解的错误；检查历史消息中的命令仅作为文本返回。
- 验证本机插件启动、宿主发现工具及一次无害调用，并在目标 Codex 宿主进行实际体验；若涉及现有网页链接，还需验证可进入正确记录。
- 参照现有公开搜索 HTTP 测试、自动归档受控来源测试、删除排除测试和浏览器交验。测试只覆盖可观察行为，预期事实不从被测输出反推；不以自动测试替代用户验收。
- 测试使用源码外的独立数据，不更改正式数据库、不重启正式服务；实现和验证后交用户体验，明确验收前不登记完成或提交。

## Out of Scope

- 改变采集启用时间、扩大历史回补范围，或采集普通 ChatGPT、Cloud 与其他应用历史。
- 恢复已取消的人工评价、纠正关系、提示改写、案例对比或重新引入已清理工具记录。
- 插件内删除／恢复、修改来源记录、运行历史命令或自动发送记录到第三方服务。
- 云端托管本机数据库、远程或移动设备访问、公开插件上架，以及新 UI 的未经确认设计。
- 本规格阶段实际实现、安装、发布插件，重启正式服务，或提交、推送、合并代码。

## Further Notes

本次请求尚未指定插件是以对话工具为主，还是还需要独立交互界面；上述只读工具与现有页面跳转是可审阅的首版提案，不代表已经获得用户确认。实施前请确认测试边界和方案；如用户期望不同，先修订规格。插件工具、宿主发现方式和可用依赖必须以本机实际能力为准，不能凭规格宣称已支持。

### 2026-10-28 实施记录

用户授权创建插件并直接修改所需部分。最终采用现有公开 Python 读取能力，新增可选只读数据库打开模式；插件包自包含读取代码，避免依赖网页进程或新增 HTTP 接口。六个只读工具已实现和本机安装。当前会话未动态载入工具，宿主实际对话体验与用户验收仍待完成。具体实现及验证见本功能任务记录和插件交验文档。
