## 已实现

- 新增 `session_catalog`，保存项目／会话身份、名称、开始与保存时间、最新快照编号及协议元数据。项目筛选、排序、计数和分页在 SQLite 执行。
- 首次启动只回填每个会话的最新快照，在服务就绪前完成，输出不含正文的计数进度；重复启动只核对轻量身份和编号。快照保存／目录更新及受管理删除／目录删除分别保持同事务。
- 项目页默认 30 条、上限 100 条；搜索会话选项按需加载和筛选。首页及自动版本检查均读取摘要，项目页空闲轮询不预取正文。
- 详情只加载选中的保存版本，日常工具视图只展示最后状态与结果，取消重复的保存观察。保存版本、原始证据、历史导出和原有完整公开查询继续保留。
- 目录详情携带原分页返回位置；搜索保留范围、命中位置和保存版本，可返回搜索结果。返回位置限定为站内目录／搜索路径。
- 新快照采用带版本头的 zlib 压缩；旧 TEXT 与新 BLOB 统一解码。`compact --backup` 要求独立新备份，以事务改写并逐快照核对原始字节 SHA-256，再执行 `VACUUM`。

目录摘要保留 `source` 协议元数据是为了兼容已有 `sessions()` 返回，不包含消息／工具正文；按需目录 API 只返回来源身份。首次回填的计时与普通页面请求分开记录。

## 真实库响应测量

SQLite 一致性备份来自正式库；初始为 4,714,029,056 字节、1,356 个快照、14 个会话。两个常用数据路径指向同一文件，未当作两个数据库。选取会话最多的项目（6 个会话）比较；真实库不足一页，分页正确性另以 65 会话夹具覆盖。

旧实现和新实现均使用该真实库副本、`serve` 模式、回环 HTTP、采集暂停。每个入口记录进程首次请求，再预热 3 次、正式采样 20 次。时间为本机完整 HTTP 响应耗时，字节为读取到的 UTF-8 响应体；没有清空操作系统缓存，不宣称是物理磁盘冷启动。

| 项目页 P95 | 732.75 ms | 33.44 ms | 32.27 ms |

新版首次回填包含在启动初始化中，测得 353.34 ms；摘要已就绪后的再次启动为 6.77 ms。首次项目请求分别为 524.18 ms、69.45 ms、42.98 ms，首次请求和预热数据分开。

项目页中位响应改善约 98.2%，P95 改善约 95.6%，HTML 减少约 25.0%。体积基线已包含前一轮目录展示，所以本轮主要改善来自避免解析完整快照。当前样本通过提案中的 P95 ≤ 500 ms、HTML ≤ 200 KiB 预算；这不是对任意数据规模或未来硬件的承诺。

复现入口：`python -X utf8 tools/measure_catalog.py --data-dir <真实库副本目录> --output <源码外报告.json>`。重现旧版时，在源码外展开固定基线，将同一测量工具放入其 `tools/`，使用新的一致副本；不要让旧程序读取已压缩的数据库。
